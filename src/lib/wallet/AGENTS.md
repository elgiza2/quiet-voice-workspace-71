- Wallets are self-custodial and built in-house from open-source @scure/@noble libraries: one phrase per account, AES-GCM sealed with an auto-created provider_api_keys `wallet_encryption` key, stored in auth app_metadata; balances come from free keyless public endpoints. Why: no paid wallet vendor or trial, and no setup steps for the owner.
- Sends and trades sign on the server only (`send.server.ts` via `/api/wallet-action`); trades use keyless aggregators (Jupiter on Solana, KyberSwap on EVM), Tron uses TronGrid with the EVM key, and the platform fee applies only when a `wallet_fee_<family>` provider key holds a receiving address. Agents may only propose sends/trades as `wallet_approval` cards that the user confirms in the browser. Why: keys never reach the browser or the model, and nothing moves without the user's tap.
