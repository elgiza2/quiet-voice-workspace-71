- Orders are priced on the server from plans.ts and only the signature-verified Kashier webhook or a Play-API-verified token can settle them, via the service-only settle_payment_order function. Why: the browser can never grant a plan or change a price.
- Subscription display prices reuse billing quotes; other-country USD quotes use the existing public FX feed for clearly indicative local equivalents, never settlement or Play entitlements. Why: local presentation must not relabel a USD charge or duplicate exchange-rate infrastructure.
- Direct card PAY payloads use kashierCardPayload with mandatory newPaymentUI=true, signed-in customer reference and enable3DS; use the returned redirectUrl verbatim and retain server confirmation. Why: Kashier's current bank-verification screen rejects the legacy payload even when initiation returns SUCCESS.
- Play product setup uses playCatalog and an operator-only dry-run-first script; retain existing mismatched products unchanged. Why: product creation and pricing must not be performed by public app endpoints or silently overwrite live terms.
